# 目标合同 · P2ray 主干质量与可回归

## ① 目标一句话

让 P2ray 的**连接 / 流量统计 / 界面 / 内核管理**这四条主干，都具备"外部命令可判、可重复跑"的证据，
并且每次发版都过同一套门禁，而不是靠执行者的说法。

## ② 验收命令（唯一判据）

```powershell
pwsh -NoProfile -File scripts/arch-gates.ps1
```

- 退出码 **0** = 全部 PASS；非 0 = 有 FAIL。
- 逐条明细见 [`gates.md`](gates.md)。G1–G4 必过；G5（真实连接下的流量统计）需加 `-IncludeTraffic`。
- **本合同的"完成"只由这条命令的结论决定**，不由提交说明、不由会话里的话决定。

## ③ 约束（不许碰）

| 类别 | 约束 |
|---|---|
| 品牌 | 不改内部标识（`ECoreType.v2rayN = 99` 等），不改协议枚举值 |
| 平台 | 不新增平台目标（仅 win-x64 / win-arm64） |
| 范围 | **不为普通节点实现 Clash 生成器**（mihomo 仅支持「自定义配置」）。要改这条必须走 ADR + 人批准 |
| 用户数据 | 不改 `guiConfigs` 现有文件格式；`dist` 构建必须保留用户配置（`scripts/test-preserve-config.ps1` 守护） |
| 依赖 | 不新增需要联网构建的依赖（离线可 `dotnet build`） |

## ④ 预算

- 单会话最多 **3 个单元**；单单元 **40 分钟**上限。
- 同一门禁**连续 2 次不过** ⇒ 停，写受阻原因。
- 长任务 goal 轮次上限由会话侧设定；到顶不许静默续轮，须重基线。

## ⑤ 停手条件（任一命中即停并写台账）

1. 预算耗尽（单元 / 时间 / goal 轮）。
2. **连续 3 个单元没有产出新证据**（只是改代码、没有新增可判输出）。
3. 验收**连续 2 次**不过。
4. 需要**人手动操作**才能验证（例如必须在界面点选）⇒ 记 `blocked`，写清需要谁做什么。
5. 发现要改目标（含 ③ 的约束）⇒ 先停，走 ADR + 批准，不许边跑边改。

## 已知限制（产品能力，不是缺陷）

| 限制 | 原因 | 依据 |
|---|---|---|
| 「按域名」「按应用」在 Xray 内核下为空 | 二者依赖 clash API，Xray 不提供；其 stats API 只有入站/出站/用户粒度 | ADR-0001 |
| mihomo 不能用于普通协议 | 普通协议配置由程序生成，只有 Xray / sing-box 两种格式 | goal ③ 约束 |
| 短连接可能漏计 | 按应用是采样式（1 秒轮询），4 秒突发约捕获 20% | ADR-0001 |
