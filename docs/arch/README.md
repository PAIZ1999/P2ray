# P2ray · 长任务架构（防跑偏）

> **为什么存在**：这个仓库的工作是跨会话、跨批次推进的。执行者（AI）会跑偏、会自称完成、会忘目标。
> 所以控制必须**外部化、文件化、可判据化** —— 不靠"记得"，靠"必须过"。
> 规则出处：`universal-architecture v2.1.3` §9（门禁）与 §17（长任务目标锁与防跑偏）。

## 文件分工

| 文件 | 是什么 | 什么时候读 |
|---|---|---|
| `goal.md` | **目标合同**六项：目标 · 验收命令 · 约束 · 预算 · 停手条件 · 版本 | 开跑前；任何改目标时 |
| `gates.md` | **门禁**：每条验收命令 + 判据 + 谁跑 + 不过怎么办 | 收工前；发版前 |
| `next.md` | **只写一个动作**（长任务不许列表式 next） | 每轮开始与结束时 |
| `state/goals/*.tsv` | **台账**：每轮一行（时刻 · 单元 · 命令 · 退出码 · 关键输出 · 判定） | 续跑时读最后一行 |
| `decisions/adr_*.md` | **决策记录**：为什么这么选，试过什么，代价是什么 | 想推翻某个设计前 |
| `scripts/arch-gates.ps1` | **判据本体**：G1–G5 逐条跑，输出 PASS/FAIL/SKIP | 由人或 CI 跑，**不由执行者自评** |

## 三条硬规矩

1. **验收命令由脚本跑，不由执行者自评。** 执行者的"我验证过了"不构成证据；
   证据是 `arch-gates.ps1` 的退出码与逐条结论。
2. **没有新鲜证据，就没有"完成"。** 不许拿上一轮的输出、不许"应该能过"。
3. **改目标先停手。** 停当前单元 → 写 ADR → 人批准 → 同回合更新 `goal.md` 与 `next.md`。
   不许边跑边改。

## 黄灯词

`应该 / 大概 / 看起来 / 我印象里` —— 出现即回读 `gates.md`，没有对应命令就先去写命令。

## 你（仓库所有者）实际会用到它的六个时刻

> 一句话：**你只做三件事 —— 定目标、看证据、签字。** 其余由执行者写、由脚本判。

| 时刻 | 你做什么 | 命令 / 看哪里 | 通过长什么样 |
|---|---|---|---|
| **开新任务** | 改 `goal.md` 四项（目标 / 验收命令 / 约束 / 预算），改完再看 `next.md` 是否只剩一个动作 | 编辑 `goal.md` | 能回答"什么命令的输出算完成" |
| **每轮开工前** | 只读两行：`next.md` 的那一个动作 + 台账最后一行 | `Get-Content docs/arch/next.md`、`Get-Content docs/arch/state/goals/g-p2ray-opt.tsv -Tail 1` | 上一轮判定是 `met` 才继续 |
| **收工 / 发版前** | 让他跑门禁，**自己看输出**，不看他的总结 | `pwsh -File scripts/arch-gates.ps1 -IncludeTraffic` | 末行 `判定: met 失败项: 0`，退出码 0 |
| **怀疑跑偏** | 让他把这一轮的动作对着 `goal.md` 的 ③ 约束逐条念；念不出来就是跑偏 | 人工对话 | 每条都能落到约束的某一行 |
| **换会话 / 上下文被压缩** | 让他先读 `goal.md` → 台账末行 → `next.md`，然后**重跑一次门禁**再干活 | 同上 | 门禁绿了才允许继续 |
| **想改方向** | 要求先停手 + 写 ADR，你批准后再动文件 | 看 `decisions/` 新增的那份 | ADR 里写了"试过什么、代价是什么" |

### 三条维护规矩

1. **`gates.md` 的判据只许收紧，不许放宽。** 想放宽必须先写 ADR 说明为什么原判据不合理。
   （本次就发生过：G5 首版拿累计值相除得到 1488 的荒谬比值，是修判据，不是放宽。）
2. **G2 的基线（180）只许上调。** 测试数减少要能说清是哪几个、为什么删。
3. **台账只追加不修改。** 判错的行留着 —— 它记录了判据本身出过什么问题。

### 怎么跟执行者说话（有效句式）

- 「跑门禁，把输出贴全」 —— 比「做完了吗」有用，后者只会得到口头结论。
- 「这条结论对应哪条命令的哪一行输出？」 —— 答不出就是没证据。
- 「这一轮的动作在 `goal.md` 的哪一条里？」 —— 答不出就是在跑偏。
- 「改方向之前先写 ADR，我批准了再动。」 —— 防止边跑边改。

### 已知边界（别指望它兜住）

- **界面长得对不对，门禁判不了**：G1–G5 只能保证不崩、数据对，视觉仍需人眼看截图。
- **G5 需要真实节点**：节点不通时只能 SKIP，SKIP 不等于通过。
- **CI 只覆盖 G1–G3**：G4 由 CI 结论本身判定，G5 必须本地跑。
